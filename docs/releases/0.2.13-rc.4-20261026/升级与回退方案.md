## 二、运行与升级方式

```text
客户端 → 固定公开主端口、分组端口 → 当前工作进程的私有本机端口
                              └→ 候选工作进程（预热时只读）
```

固定监听器负责公开端口、认证、请求暂存与版本交接。每个工作进程有自己的私有主端口和分组端口，只监听本机；不能自行抢占公开端口。主端口、分组列表、管理响应与状态 SSE 都显示实际公开地址。

正常在线升级顺序：

1. 校验候选包、平台、代码身份、数据目录以及启用的分组；候选先只读启动，不探测供应商、不写配置和用量。
2. 候选预热通过后，公开监听器暂存新请求，旧请求和 SSE 继续运行。
3. 等旧请求、用量、探测和后台 413 诊断落盘完成，再让旧进程只读，转移唯一写入权。
4. 激活候选，重读最新配置、分组与用量，放行排队请求；请求只发送一次。
5. 至少连续三次健康检查成功，并经过完整的连续健康观察窗口后，才退出旧工作进程。默认检查间隔 5 秒、连续窗口 30 秒，正常演练约 35 秒完成观察。
6. 观察期内崩溃时优先恢复保留的旧进程；旧进程已退出时，重新启动保留的回退包。保留包仍会重新读取最新数据。

健康检查只访问本机状态接口，不调用供应商。异常只告警并保留活动连接；健康检查超时会重新计算连续观察窗口，因此观察不是无条件在固定秒数后结束。此前刻意暂停工作进程的演练已验证：异常期间不丢弃旧进程，恢复后重新完成连续观察。

每段稳定观察期间最多自动恢复一次。恢复进程尚未稳定便再次退出时，保留公开监听器，返回 `handoff_recovery_exhausted`，停止自动重启循环。完整稳定观察通过或操作者明确升级/回退成功后，才重新允许一次自动恢复。事件保存在指定数据目录的 `handoff-events.jsonl`，权限为 `0600`。

## 三、数据、管理与边界

- 监督器与排空中的子进程共用所有权登记，原进程尚未退出时禁止其他实例接管数据目录。写入租约核对 PID、实例及 epoch，存活持有者不能仅因 TTL 到期而被抢占。
- 配置、用量、价格实验、诊断和事件日志都固定到指定独立数据目录。数据目录不能位于版本包内，关键数据路径不能通过软链接指向其他项目。
- 后台诊断必须等日志追加完成才算结束；优雅停止也会等待后台写入。只读准备超时后，后续激活使旧准备失效，迟到回复按请求编号区分。
- 动态分组支持新增、复制、启停、换端口；先预留公开端口，再保存和提交。失败保留旧配置与监听，已经保存的配置以磁盘为准。分组端口变更与版本交接互斥。
- 管理写入串行，避免失败恢复覆盖并发设置；复制分组只复制配置，不复制用量。公开认证与 Cookie 保留，管理令牌不会传给上游。
- 正常请求保留原有 200 MB 上限；交接队列独立限制为最多 32 条、16 MB、等待 30 秒。超限返回明确错误；客户端取消则移除排队请求。
- 活动请求超过 30 秒交接排空期限时取消本次升级、恢复旧版本，保留既有 SSE；不会为了更新强杀业务连接。
- 已经随崩溃进程断开的请求无法恢复，不自动重放或拼接输出。固定监听器自身崩溃也不能保留其公开连接；这种情况按人工应急恢复处理。
- 回退恢复代码，继续使用最新配置和追加用量，**不以旧数据备份覆盖新增用量**。已经落盘的历史不会因代码回退而倒退；崩溃瞬间尚未完成落盘的请求不属于无损承诺。
- 首次从原入口迁移到固定监听器，需要一次人工维护窗口。此后的工作进程在线升级才由固定监听层接续；更新固定监听器本身同样需要另行安排维护。

## 六、后续在线操作与应急恢复

固定监听入口运行后，在另一个终端使用同一数据目录发命令，无需先停止公开监听器：

```bash
./.venvs/0node/bin/node tools/lite-ccswitch/releases/0.2.13-rc.4-20261026/handoff-runner.mjs \
  status --data-dir tools/lite-ccswitch/data

./.venvs/0node/bin/node tools/lite-ccswitch/releases/0.2.13-rc.4-20261026/handoff-runner.mjs \
  upgrade --data-dir tools/lite-ccswitch/data --candidate /绝对路径/下一已验收版本包

./.venvs/0node/bin/node tools/lite-ccswitch/releases/0.2.13-rc.4-20261026/handoff-runner.mjs \
  rollback --data-dir tools/lite-ccswitch/data
```

控制通过当前用户专用 Unix 套接字，目录 `0700`、套接字 `0600`。`status` 返回当前包、PID、交接阶段、回退位置、健康观察和事件日志错误。命令返回成功才算切换完成；仅看到新包文件或修改源码不算完成。旧进程仍处于观察期时，不开始下一次升级。

若固定监听入口本身异常，需要人工回到原始生产入口：先正常停止该监督器并等子进程全部退出；重新校验原始 0.2.12/0.2.11 包，再使用原始包自己的监督器代码启动。不要删除租约、强抢端口或恢复旧用量文件。

```bash
./.venvs/0node/bin/node tools/lite-ccswitch/releases/0.2.12-20261024/release.mjs run \
  tools/lite-ccswitch/releases/0.2.12-20261024 \
  --fallback tools/lite-ccswitch/releases/0.2.11-20261024 \
  --data-dir tools/lite-ccswitch/data \
  --port 15720
```

只有用户再次发出停止信号，才强制断开已有连接。监督器意外死亡但子进程仍在排空时，所有权锁会拒绝新实例接管；先核实排空与进程状态，不绕过锁。

## 七、未来版本的固定工作顺序

每一版均依次完成：独立源码和数据副本 → 对应 Node 版本回归 → 生成新目录的版本包 → 上一业务实现与候选的主/分组长流交接及崩溃回退 → 包校验与实际归档恢复 → 给用户具体合并结果 → 用户决定合并和生产切换。
