# 2026-08-08 SSE 超长前导恢复

## 现象

使用本项目 `127.0.0.1:15720` 的 Responses API 时，Codex CLI 出现：

```text
Unexpected status 502 Bad Gateway: SSE 前导数据超过限制: 65536 bytes
```

使用日志显示，多个供应商在首包探测阶段都出现 `stream_protocol`，且不计入供应商断路器。部分供应商还会返回模型不可用，但这不是本次 502 的主因。

## 根因

代理原本在将 SSE 数据交给客户端前，要求满足以下任一条件：出现正文/工具调用等语义事件、出现完成事件、或收到两个可解析 SSE 事件。

部分上游会先发送 `response.created`，随后发送很长的推理类或其他非正文 SSE 前导。前导超过 64 KB 时，旧逻辑未把它视为正常流，提前中止并向 Codex CLI 返回 502。

## 处理

1. 将 Responses API 的 `*.delta` 事件，以及 Chat Completions 的推理增量，识别为正常流内容。
2. 已验证至少一个正常 SSE 生命周期事件后，若前导超过 64 KB，继续转发并让后续流处理器持续识别错误和终止事件。
3. 纯随机超长文本、首包阶段的结构化鉴权/限流/模型错误、以及没有任何有效 SSE 事件的流，仍保持原有拦截行为。

这只是响应解析规则调整，不会主动发起探测请求，不增加额外 Token 消耗。

## 恢复与验证

修复后对 `15720` 执行一次优雅重启，不停止 Codex CLI。CLI 保持原会话并自动重连；随后同一模型请求经 `cx1` 返回 HTTP 200，说明超长前导不再被误判。

回归测试覆盖：

- 单条超过 64 KB 的推理增量；
- 已出现 `response.created` 后的超长 SSE 前导；
- 首包阶段的结构化错误识别；
- 无法解析的超长数据仍不计入供应商断路器。

本次共通过 23 项测试。
